# Local engine API

`python3 engine/pdf_engine.py OPERATION INPUT... --output NEW_PATH` accepts JSON options through `--options` or, preferably, `PDF_OPTIONS_STDIN=1` and standard input. Passwords must use standard input. `--capabilities` reports engine version `0.6.0`, the operation list and detected dependencies. Existing dependency keys are retained; `pyhanko`, `java` and `verapdf` report module presence, an executable Java path, and the pinned veraPDF JAR SHA-256 respectively. `independent_standards_validation` is true only when Java and the verified JAR are available. `dependency_status` distinguishes missing, unreadable and altered JARs without disclosing filesystem paths; the probe does not launch Java. Success writes one JSON object with `ok` and `output`; failures write JSON to stderr and exit nonzero; cancellation uses code `Cancelled` and exit 130.

The macOS application uses [`EngineInputTransport`](../Sources/PDF/EngineInputTransport.swift): JSON of at most 64 MiB is written to an exclusive `0600` regular file inside a random `0700` directory. After opening its read handle, the application immediately unlinks the file and removes the directory; the child receives the remaining seekable standard-input descriptor. Options are not placed in process arguments. This avoids blocking a pipe when a child exits before reading a large review. The descriptor can contain readable document text, passwords, certificate PINs or an API key; this is neither encryption nor RAM-only storage. After initialization, closing the last descriptor, including process loss, releases the unlinked file. A crash between the initial write and unlink can still leave a private named file; there is no universal crash-cleanup guarantee. Other subprocess transports, including qpdf job/patch JSON, have separate private-file lifetimes. CLI clients can still supply JSON through their own stdin. `digital-sign`, signing workflows, `signature-request-send` and `signature-request-status` explicitly require `PDF_OPTIONS_STDIN=1`.

## Preservation and cancellation

Inputs are never overwritten. Results are staged in a private temporary directory on the destination filesystem and published with an atomic no-replace primitive. Existing destinations and symlinks are refused, including creation races. Failed operations leave no final output. File publication uses hard links; directory publication uses macOS `renamex_np(RENAME_EXCL)` or Linux `renameat2(RENAME_NOREPLACE)`. Filesystems must support those primitives.

Existing PDF encryption is retained for PDF modifications. Merge, multi-input organize and split rebuild protection with AES-256, a supplied password and preserved permissions. Merged permissions are the intersection of protected inputs. An explicit output_password chooses the resulting credential; differing protected input credentials require it. Unlock is an explicit operation. PDF/A rejects encrypted sources because PDF/A cannot be encrypted: precede conversion with an explicit unlock. Non-PDF exports necessarily use the destination format's normal protection characteristics.

External converters run in a dedicated process group. The owner retains the unreaped leader until its final group signal, then collects that leader; it never signals a recycled group ID. CLI cancellation, SIGINT, SIGTERM and timeout unwind this cleanup. Signal, inspection or collection failures remain errors and must not be presented as confirmed cleanup. SIGKILL, power loss and a process crash cannot run cleanup and may leave converters or private staging alive. Operations become committed when atomic publication succeeds; cancelling after that point does not delete a completed result.

On macOS, signaling an all-zombie group can return `EPERM`. The bundled, read-only `pdf-process-group-check` accepts that case only after exit observation and complete, stable, matching `libproc(arg=1)`/`sysctl` inventories that include the retained leader and contain only zombies. It neither signals nor collects processes. Missing, malformed, inconsistent, inaccessible or live groups remain errors; an invalid bundled helper cannot silently use `ps`. The helper is compiled and signed during source installation or packaging, without requiring a compiler on the binary destination Mac. The [two-system diagnostic](../docs/evidencias/process-6bb7d0f/README.md) demonstrated the kernel behavior; approval with the complete runtime still requires the integrated matrix.

Standalone diagnostics and runtime validation install cooperative signal handling explicitly at their CLI boundary, without import-time changes to a caller's policy. Portable validation distinguishes direct process-group cleanup from transitive cleanup: any failure/interruption after starting workloads preserves its private IPC namespace and records uncertainty. A collected checker alone cannot prove that a converter in another session finished.

Installed applications also retain a cooperative bundle lease through [`BundleRuntimeLease`](../Sources/PDF/BundleRuntimeLease.swift) and [`runtime_lease.py`](runtime_lease.py). Normal use holds a shared lock; an installer retains its exclusive lock across validation. The bootstrap validates the actual descriptor/inode and lock mode, preserves private stdin and execs the bundled engine or the permitted qpdf in the same process. The engine explicitly passes the lease to direct converter children, so killing the engine alone does not release a live cooperating child's protection against bundle replacement. Native helper processes use a separate validated descriptor transport. This protects the installed bundle, not document transactions; third-party descendants that close inherited descriptors, arbitrary external programs and power loss are outside the protocol. Environment values carry lock identity/mode, never options or passwords.

## Shared options

- `password`: input PDF password; `second_password`: second comparison input password when different. Merge/organize accept `input_passwords:["", "secret", ...]`, exactly one credential per input, and optional `output_password` (8–40 characters). Values must be sent through stdin, not command-line arguments.
- `pages`: one-based selector such as `1,3-5,8-6`; omission means all pages. `organize`, `extract-pages` and split groups preserve duplicate selections and ordering; other operations deduplicate. Repeated output pages have independent page objects, so a later edit to one copy does not change another.
- Coordinates are points from the upper-left of the visible, unrotated page, relative to its existing crop box. `rect: [x0,y0,x1,y1]` or `x,y,width,height` defines a bounded area. Rotated page bounds are derotated before validating edits.
- Text accepts `text,font_size,font,color,opacity,position,margin`; colors are `#RRGGBB` or RGB components 0–1. Supported `position` values: `top-left`, `top-center`, `top-right`, `center`, `bottom-left`, `bottom-center`, `bottom-right`. `font` uses PDF standard names (`helv`, `hebo`, `heit`, `tiro`, `cour`, etc.); overlays can use `font_file` for custom fonts. Unicode overlays and replacement text use MuPDF HTML shaping and its bundled fallback fonts; unavailable glyphs or text that cannot fit are refused. An explicit font file must contain every requested glyph. `rect` uses a bounded textbox; otherwise `x,y` overrides the baseline position.

Structured scan settings are shared by `form-detect`, `word` and `excel`: `source:"auto"|"vector"|"ocr"`, `language:"eng"` (Tesseract language packs required), `ocr_dpi:200` (120–400), `ocr_psm:6` (3–13), `min_confidence:35` (0–100), `table_detection:"ruled"|"aligned"` and `ocr_deskew:false`. Markdown keeps its previous vector/image behavior by default; `source:"auto"` or `"ocr"` explicitly enables structured OCR there. Low-confidence words remain in exports and are flagged for review; the threshold never silently deletes source text. Confidence measures OCR evidence and is not a calibrated accuracy probability. The parser rejects malformed TSV, nonfinite/out-of-bounds coordinates and absent language data. Limits are 40 million rendered pixels/page, 2 million rule-intersection pairs and 4,096 cells/grid.

Raster ruled tables require a strong rectangular outer frame and unambiguous present/absent interior edges. Connected cells must form complete rectangles; partial/broken borders and L-shaped merges are refused. Accepted merges become actual DOCX/XLSX merged cells; Markdown retains cell text without merge semantics. Overlapping table candidates that consume the same OCR words are discarded as tables, retaining those words as prose. Exports remove table words from surrounding prose by their exact recognized indices, not merely an enclosing rectangle. Explicit `table_detection:"aligned"` also accepts 3–1,000 rows of 2–12 complete aligned columns, separated by gaps larger than `max(12 pixels, 2 × word height)`, with consistent left/right/center alignment and a numeric column in at least 80% of data rows. This is geometric evidence, not general semantic table recognition.

Rule suppression is conservative: only thin straight borders with supporting rectangular topology are eligible. A standalone underline also needs blank adjacent bands, so a connected glyph stroke is not erased or proposed as an empty field. Thick, touching or ambiguous shapes remain in the OCR image and need manual review; this does not prove general recognition accuracy. Original PDF/image bytes remain unchanged.

`ocr_deskew:true` estimates only ruling-grid inclination: the search uses a sample at most 1,000 pixels on its longest edge, requires at least two long rules per axis and a valid rectangular grid, and applies a 0.5°–7° correction only with at least 35% stronger line evidence. Text-only scans or insufficient evidence remain unchanged. The corrected OCR-only image must also fit the 40-million-pixel limit. Detected boxes and all four corners are mapped back to the original crop-relative unrotated page, with `preprocessing` evidence and `quad` coordinates in analysis reports. Page rotation and crop boxes are handled explicitly. Source PDF/image bytes are unchanged; rotation and line removal occur only in the temporary OCR input. Handwriting, damaged/noisy borders and general skew correction remain unsupported or require manual review.

For existing ComboBox/ListBox fields, `forms` normalizes both PDF `/Opt` strings and `[exportValue, displayLabel]` pairs into `choices:[exportValue,...]` and `choice_labels:{exportValue:displayLabel}`. `form-fill` accepts the exported value, displays its label in the appearance, and preserves `/Opt`; `""` clears the selection. The interface shows labels while sending exported values. Label glyphs follow the existing Latin-1 form-appearance constraint.

The `ocr-page` transport accepts regular PNG files, refuses final symlinks/FIFOs and checks that bytes did not change while reading. Limits: 128 MiB encoded input, 40 million pixels, 30,000 pixels per dimension, 50,000 words, 64 KiB per word, 8 MiB total recognized text, and 16 MiB TSV/JSON. It strips source metadata before recognition, uses private temporary files/directories, and writes the final JSON with mode `0600`. A separate language preflight (10 seconds maximum) requires every requested pack: Tesseract's ability to continue after dropping a missing language is explicitly refused. Recognition uses automatic page segmentation (`--psm 3`) and a 60-second limit, with the engine's existing process-group cleanup on cancellation. A genuinely blank recognized image returns an empty observations array; malformed inputs/results, absent language data and process errors fail without publication. Converter error text is sanitized so it cannot leak recognized content or private source paths.

## Inspected original content and reviewed OCR

`content-inspect` takes one PDF and optional `pages,password`, writing private JSON:

```json
{"version":1,"source_sha256":"…","page_count":2,"pages":[{"page":1,"width":500,"height":650,"rotation":90,"cropbox":[0,0,500,650]}],"objects":[{"id":"…","kind":"text","page":1,"rect":[30,40,200,60],"text":"Original","font":"Helvetica","font_size":14,"color":"#000000","font_status":"original","substitution_font":"MuPDF Unicode fallback (sans-serif)","editable":true,"limitations":[]}]}
```

Widths, heights and rectangles are **unrotated**, relative to the visible crop box; page rotation is separate. Image records add pixel `width,height` and `supported_actions`. IDs bind the exact source SHA-256, page, object, text and geometry. Editable candidates are isolated horizontal text runs, compatible paragraph groups and uniquely placed, axis-aligned images. Paragraph records use `kind:"paragraph"`, flat `member_ids` referring to original text runs, inferred `alignment` and a `line_spacing` multiplier. Groups require consecutive lines of one source block, homogeneous style and compatible baseline distances/alignment; individual member runs remain available. These are bounded geometric groups, not inferred document-wide semantics. Overlapping/rotated text, interactive overlaps, pending redactions, inline/shared/masked/transformed images and out-of-page objects are identified with explicit limitations. Text under later graphics, internal clipping or unusual transparency groups is refused rather than brought to the front or exposed. Clipped images can only be replaced in place or deleted; moving them could expose hidden pixels. A rectangular clip containing the entire visible page, such as its crop box, is safe. This is a bounded editor, not an arbitrary PDF content-stream reconstruction claim.

`content-apply` takes the same PDF with `source_sha256,edits,password`. Each edit has `id,action` (`replace`, `move`, `delete`). Text may specify `text,rect,font_size` (4–300), `alignment` (`left,center,right,justify`), `color`, `font_file`, and `allow_font_substitution:true`. Paragraphs reflow within the chosen rectangle and accept `line_spacing` from 1 to 3 times the font size. Editing a group and any of its members in the same transaction is refused. Paragraph destinations cannot overlap other source text, images, vectors or interactive objects; overlapping planned paragraph edits are also refused. An unambiguous extractable original font is reused; unavailable glyphs require explicit substitution consent. Explicit font files must contain all glyphs. MuPDF's bundled shaping/fallback fonts are used only after consent; identical typography is not promised. Overflow and overlap with another original text run fail atomically. Image `replace` requires `image_path` and preserves its original rectangle and stacking order; use `move` separately for geometry changes, with an otherwise free destination. Deletion here edits content; use the redaction tool when metadata, attachments and other copies also require sanitization. Existing source encryption and permissions are retained; no password change is implied.

`ocr-review` performs actual Tesseract recognition on selected raster-only pages. Searchable pages are refused to prevent duplicate text layers; select the scanned pages of a mixed document. Options are `pages,password,language,ocr_dpi,ocr_psm,min_confidence,ocr_deskew`, with the structured-scan settings above. Output JSON has `version:1,source_sha256,page_count,backend:"tesseract",language,settings,pages,words,review_required:true,review_sha256`. Each word contains `id,page,rect,text,confidence`; confidence is **0–1**, not percent. Page geometry follows the same unrotated convention. When `ocr_deskew` is explicitly supplied it is retained in settings; when true, page records include preprocessing evidence and words include inverse-mapped quads. Omitted options retain the prior canonical report format. Original image pixels are never changed.

The native OCR-review interface explicitly offers automatic page layout (`ocr_psm:3`), a uniform text block (`6`) and sparse text (`11`). New UI requests select automatic layout; the engine API default remains `6`. Loaded reports retain their actual language/segmentation settings, including legacy reports without the optional native-decoded settings. Changing pending UI options does not replace the current review or the report used by export until recognition completes again.

`ocr-apply` takes `source_sha256,password`, either the complete `review` object or `review_path` pointing to its regular local JSON file, and `corrections:[{"id":"…","text":"corrected"}]`. The two review transports are mutually exclusive. Geometry/IDs cannot be supplied in corrections. The engine re-recognizes the unchanged source with the same settings and requires the complete review to match before adding a transparent searchable Unicode layer; a recomputed client hash alone cannot authorize forged rectangles. Corrections that cannot fit the original word area fail without output. Raster pixels, unselected pages and original encryption are retained. Applying a review after changing the OCR engine/data may require a fresh review. Deskew quads are bound and revalidated, but the searchable text is placed within each original axis-aligned enclosing rectangle; glyphs and form widgets are not drawn at arbitrary angles. This is searchable text recovery, not exact rotated typography reconstruction.

Limits: source PDF 256 MiB; JSON 32 MiB; 100,000 inspectable objects; 10,000 text runs/page and one million overlap comparisons/page; 1,000 content edits; replacement text 64 KiB; image 64 MiB/40 million pixels; font 32 MiB. OCR review accepts 50,000 words/8 MiB text, corrections up to 4,096 bytes each, without line breaks or tabs. Latin OCR reuses one invisible font resource per page; complex Unicode shaping is limited to 2,000 words per application to bound memory, so larger documents should be reviewed in page groups. Original embedded editing fonts are cached by source font identity, rather than copied for each span. Input assets/review JSON refuse final symlinks and nonregular files and check for changes during reading. Outputs use mode `0600` and the engine transaction/no-replace publisher. External OCR failures are sanitized; recognized text and private paths are not logged. Process-group cancellation remains active.

`conversion-audit` accepts exactly two inputs: the original PDF and its converted DOCX/XLSX/PPTX/ODT/RTF file. It converts a private stable snapshot of the actual Office file back to PDF using LibreOffice. The atomic output directory contains `roundtrip.pdf`, a self-contained `comparison.html` and `report.json`. Options: original PDF `password` and Office `fit_width,orientation,landscape`. All pages are compared; the limit is 500 pages per document and 40 million pixels/page in the HTML renderer. The report records all three SHA-256 hashes, actual editable XML object counts (RTF is explicitly uninspected), page counts/sizes, page-aligned mean pixel differences, word-count overlap, font-name differences and text outside page bounds. Font names can suggest substitution but do not prove matching glyphs; word overlap ignores order; invisible Office frame overflow cannot be universally detected. No conformance or perfect-fidelity claim is inferred. The comparison necessarily displays document content, including a password-opened PDF, in private report files; it never changes the source protection. ZIP/XML inputs have bounded size and reject duplicate entries and entity declarations.

Vector extraction uses `table_detection:"ruled"` by default. A complete, nonoverlapping rectangular cell tiling can produce real horizontal/vertical DOCX and XLSX merges, with each covered nonanchor cell required to be empty. Ambiguous geometry is retained as ordinary text instead of discarding it as an assumed table. Explicit `table_detection:"aligned"` also considers borderless aligned text: 3–1,000 rows, 2–12 columns, at least 80% occupied cells, at least two occupied cells per row, and a repeatedly numeric column are required. This deliberately misses tables without adequate evidence; it is not general semantic table recognition. Raster OCR uses the separate measured-grid and explicit aligned contracts above. Footnotes, recurring headers and arbitrary multilevel layouts are not universally reconstructed.

`--check-workflow-dependencies` accepts only a JSON array of workflow stages on stdin (at most 1 MiB), validates the same stage allowlist and checks required dependencies without executing the workflow. It cannot be combined with operation/input/output/options arguments; success reports `{"ok":true,"dependencies_checked":true}`.

Generic workflows use an explicit operation allowlist. Source-bound `content-apply`, `ocr-apply`, accessibility remediation, dossier assembly, conversion audit and all signature-request operations require their own review/interface and are refused in generic workflows or batches. Read-only content/OCR/accessibility/print inspection and measurements are JSON terminal outputs. Excel's expanded extraction retains surrounding prose, so table headers may begin after that prose; clients should locate headers rather than assume a table always starts at A1.

## Printing and legal production

| Operation | Options / output and limits |
|---|---|
| `print-preflight` | JSON with source SHA-256, page boxes, embedded-font inspection, effective image DPI/color-space names and OutputIntents presence. `minimum_dpi` defaults 200 (36–2400). It does not validate the ICC content, separations, overprint, color fidelity or PDF/X conformance; `independently_certified:false` is explicit. |
| `print-prepare` | PDF with `trim_inset` (default 18 pt, 0–144), `bleed` (8.5 pt, 0–72), optional `pages`, `crop_marks:true`. Bleed must fit inside the inset; marks require remaining space. | `pdfx` | A Ghostscript PDF/X-3:2002 candidate using an explicit regular CMYK `icc_profile` (128 bytes–16 MiB) and ASCII `output_condition` (1–120 characters). Encrypted sources are refused. It does not manage uniqueness across separate runs or provide a chain-of-custody ledger. |

## Resource policy

The application computes a CPU/memory/thermal/low-power budget before a job and supplies `PDF_WORKERS`, `OMP_THREAD_LIMIT`, `OPENBLAS_NUM_THREADS` and `VECLIB_MAXIMUM_THREADS`. OCRmyPDF uses `resource_budget.worker_count()` for its actual `--jobs` value, bounded by processor count and estimated physical memory. `PDF_MEMORY_BUDGET_BYTES` records a policy estimate; it is not an operating-system memory cap. The engine does not force every converter to obey a common worker pool, adjust a running job continuously or report measured Neural Engine use. See [the roadmap audit](../docs/AMPLIACOES-2026-10.md) for hardware and benchmark evidence.
